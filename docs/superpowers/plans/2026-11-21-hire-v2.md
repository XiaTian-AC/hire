# hire v2 实施计划

> **给执行代理：** 必备子技能：superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans，逐 task 执行。进度勾选一律走 OpenChamber knowledge todo（挂本 plan），本文件不写 `- [ ]` 勾选表。

**Goal:** 一次破坏性发布交付 hire v2：任意语言 taskfile（适配器契约 + 用户自配运行时 + cpp 编译缓存）、吸收旧 v2 全部决定、改名 tkx → hire、产品体验补齐与审计修复。

**Architecture:** internal/adapter 三适配器（内嵌 lua / 内建 toml / 外部 exec 契约）统一产出 `Task{Name,Desc,Args,Fn}`，多文件经 `Chain` 合并后下游 runtime/bg/cli 零感知适配器差异；cli 查找链探测五文件、全局先 cwd 后；bg 层经 `HIRE_FILES` 环境变量向子进程交接文件列表。

**Tech Stack:** Go 1.27 标准库 + gopher-lua（既有）+ BurntSushi/toml（唯一新增依赖）；Python/Node/g++ 为用户侧运行时，不是本项目依赖。

**Spec:** docs/superpowers/specs/2026-11-21-hire-v2-design.md（执行者须同读；旧稿 2026-08-30-taskfile-v2-design.md 为吸收来源，其 §3-§8 细节仍有效）。

## 全局约束

- Go 1.27；依赖上限：gopher-lua + BurntSushi/toml，不新增其它
- 单二进制；Windows 一等公民（路径含空格/中文必须全程可用）
- 标识符前缀一律 hire：module `hire`、契约动词 `__hire__`、环境变量 `HIRE_ARGS` / `HIRE_FILES`、配置目录 `~/.config/hire/`、数据目录 `~/.local/share/hire/`
- 查找链固定五文件 `Taskfile.{toml,lua,py,js,cpp}`；`.mjs`/`.cc` 仅 `--taskfile` 显式有效
- 加载序：全局先、cwd 后；同名任务 cwd 赢 + stderr 警告（含来源文件）；`shell =` 声明同规则
- x.run 仅同文件；每 Lua 文件独立 LState；TOML 内联 run 在其文件专属 LState；跨文件不互调
- cpp 缓存键 = sha256(源文件内容 + "\x00" + 解析后 build 命令串)
- 旧 v1 Lua 语法不兼容，无迁移层
- 验收命令：`go test ./...` 与 `go test -tags integration ./integration/`（CI 同款，合并前本地原样跑一遍）

## Review Focus（spec 隐含、任务测试必须钉死的五类输入）

1. **Windows 路径含空格/中文** → build 模板经 shell 展开后 `{out}`/`{src}` 仍可引用 → 测试钉在 Task 4
2. **discover 畸形输出**（非法 JSON / 半截输出 / 非零退出）→ 报错含文件名与 stderr 摘录，不 panic → Task 4
3. **HIRE_ARGS 值含空格/引号/中文/换行** → JSON 序往返后样板回显一致 → Task 4
4. **全局与 cwd 同名任务** → cwd 赢 + stderr 警告 → Task 6
5. **bstart 后 taskfile 被删** → `_run` 子进程把"文件不存在"写进日志，非静默 → Task 6

### Task 2: adapter 包 + LuaAdapter（v2 简化语法重写）

**Files:**

**Interfaces:**
- Produces（后续全部任务依赖）:

```go
type Task struct {
    Name, Desc string
    Args       map[string]argparse.Spec
    Fn         *lua.LFunction
    File       string            // 来源文件，警告与 x.run 归属用
}
type File struct {
    L            *lua.LState      // 每 Lua 文件独立 VM
    Tasks        map[string]*Task
    Order        []string
    DefaultShell string           // shell = "..." 顶层声明
}
func LoadLua(path string) (*File, error)

type Chain struct {
    Files        []*File          // 加载序：全局在前、cwd 在后
    Tasks        map[string]*Task // 同名后者（cwd）赢，构造时 stderr 警告
    Order        []string
    DefaultShell string           // 后加载者覆盖
}
func NewChain(files ...*File) *Chain
// runtime.Run 改签名: Run(c *Chain, name string, args *lua.LTable, opts Options) error
// callTask/x.run 用 task 所属 File 的 L 执行（同文件约束由此天然成立）
```

**行为要点（旧 v2 §3/§3.2）：** 快照差分收集——DoFile 前注入 `task`/`req`/`bool` 并快照 `_G`，新增或值变化的键才是任务候选；类型分派：string→单命令、全 string 的 table→命令序列、function→裸函数、带 `__hire=true` 隐藏标记的 table→完整任务、未标记 table→报错提示 task{}；顶层 `shell = "..."` 提取为 DefaultShell 不是任务；保留名报错：任务名 `__` 前缀、**参数名 `shell`（审计 #6）**；旧语法（return 表且差分为空）→ 明确报错"v1 语法已移除"；`when={os=...}` 不匹配则任务不存在。字符串/数组简写任务合成为执行命令序列的 LFunction（走与 ctx:sh 相同路径），合成细节由实现者定。

**Steps:**
1. 写失败测试 `lua_test.go`：四种声明形式各自可被 ls/run；保留名报错（`__` 前缀、参数名 shell）；旧语法拒绝；when 过滤；shell 顶层声明提取；快照差分不误收内置名（重定义 print 为任务、内置 string 等不误收）
2. `go test ./internal/adapter/` → 红
3. 实现 adapter.go + lua.go（runner/cli 引用同步改）
4. 同命令 → 绿；`go test ./...` 全绿

### Task 4: ExecAdapter + runtimes 表 + cpp 编译缓存

**Files:**
- Create: `internal/adapter/exec.go`、`internal/adapter/runtime.go`
- Modify: `internal/config/config.go`（Load 增返回 runtimes）
- Test: `internal/adapter/exec_test.go`、`runtime_test.go`（python/node 缺失时对应用例 `t.Skip`）

**Interfaces:**
- Consumes: Task/File/Chain
- Produces:

```go
type RuntimeSpec struct {
    Cmd   string // 非空 = 解释型命令（如 "python3"）
    Build string // 非空 = 编译型 build 模板（{out}/{src} 占位）
}
func ResolveRuntime(ext string, rts map[string]RuntimeSpec) (RuntimeSpec, string, error)
// 返回 (spec, runtime名, err)；runtime 名用于缓存目录 <lang>/
func LoadExec(path string, spec RuntimeSpec, rtName string) (*File, error)
// config.Load 签名追加第四返回值: runtimes map[string]RuntimeSpec
// config.lua: runtimes = { python = "python3", node = "node",
//   cpp = { build = "g++ -std=c++20 -O2 -o {out} {src}" } }
```

**契约（spec §5）：** discover = `<Cmd> <path> __hire__ discover` → stdout JSON `{"tasks":[{name,desc,args}]}`；畸形 JSON / 非零退出 → error 含文件名与 stderr 摘录。`Task.Fn` = Go 闭包：`<Cmd> <path> __hire__ run <name>`，`cmd.Env` 追加 `HIRE_ARGS`（已解析 flags + `"_"` 位置数组的 JSON），stdio 继承，非零退出 → error `task %q failed (exit N)`。Task.Args 从 discover 的 schema 转入（argparse 校验照旧走 cli 层）。编译型：缓存键 sha256(源内容 + "\x00" + Build 命令串) → `<cachedir>/hire/<rtName>/<hash>.exe`（cachedir = XDG_CACHE_HOME 或 %LOCALAPPDATA%）；命中直跑，未命中先经用户默认 shell 执行 Build 再跑；编译失败报错附完整输出。扩展名内建映射：.py→python、.js/.mjs→node、.cpp/.cc→cpp；未注册 → 报错列出已注册 runtime 与已知扩展名。

**Steps:**
1. 失败测试（含 Review Focus 1/2/3）：python echo 任务 discover+run 往返、HIRE_ARGS 含空格/引号/中文/换行值的回显、畸形 JSON 与非零退出报错、runtimes 表字符串/表两形态解析、缓存命中/未命中/改 Build 串即失效、含空格路径的 build 模板展开、g++ 缺失时 cpp 用例 skip
2. 红 → 3. 实现 exec.go + runtime.go + config runtimes → 4. 绿 + 全量绿
5. Commit: `feat: exec adapter with runtime registry and cpp compile cache`

2. 红 → 3. 实现 → 4. 绿 + 全量绿
5. Commit: `feat: persistent shell instances with sentinel protocol and export mode`
